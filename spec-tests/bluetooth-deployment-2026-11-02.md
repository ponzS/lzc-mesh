## 实现与部署

- LPK、中枢、Mac、Omarchy 客户端版本 0.3.0；Mac/GTK 与页面提供自动、仅蓝牙、仅局域网、仅中转四种账号级模式。
- 蓝牙使用经典 RFCOMM 字节链路、Rustls 双向证书认证及既有控制会话。严格蓝牙模式不创建 QUIC UDP 端点、不回退中转。
- 发送前合并相邻待发位置，保留按钮、按键与动作屏障；已加密 TLS 字节不丢弃。
- Mac 签名辅助应用隔离系统蓝牙初始化，通过权限 0700 的临时目录和 0600 FIFO 与主客户端交换加密字节。停用时请求移除 SDP 服务，目录撤销与父进程退出均触发辅助应用停止。
- Omarchy 使用宿主机的私有 Unix 描述符桥接。桥接仅提供出站 RFCOMM 连接与能力查询，无 IP 监听、命令、文件或输入注入接口；连接后通过 SCM_RIGHTS 交给桌面客户端，数据不经 IP 转发。

## 已通过的检查

1. 宿主 BlueZ 与适配器可用。容器虽然可见 hci0 的 sysfs 节点，独立网络命名空间仍拒绝 AF_BLUETOOTH；挂载 /dev 本身不足以解决。
2. 普通 UID 可以创建 RFCOMM。已在用户核对验证码后完成 Mac 与微服配对，并恢复宿主原来的不可配对状态。
3. 宿主用户级服务启动后运行 UID/GID 均为 65534，CapEff/CapPrm 均为零，NoNewPrivs=1。Omarchy 通过私有 Unix 套接字能力查询成功，取消拨号后桥接仍可响应。
4. 图形方式启动的 Mac 测试应用与宿主真实 RFCOMM 回显通过。200 次持续往返：p50 31.91 ms、p95 59.96 ms、最大 79.91 ms。此前 20 次低频首轮测试最大约 488 ms。这是测试数据往返，不是光标单程延迟或显示延迟。
5. 共享传输核心 12 项测试通过，包括真实 TLS 字节互通、陌生证书拒绝、无信任集关闭套接字、位置合并与点击顺序、蓝牙严格模式不发布 UDP/不回退、既有 QUIC 与中转回归。TLS 字节测试不代替真实蓝牙客户端验证。
6. 中枢 16 项测试通过；页面 JavaScript 语法检查、Linux 编译、便携包及 Arch 包构建通过。Arch 包禁用外层 GCC LTO，Rust 静态库自身仍使用 ThinLTO，避免 ring 原生汇编链接失败。
7. Mac universal 主程序与辅助应用编译、签名和安装包校验通过；维持原开发签名身份。
