# Mac → Omarchy 接收侧主循环阻塞修复（v0.2.3）

Linux 暂时仅支持 Omarchy（Hyprland）。本次修复整理为 v0.2.3，不移动既有 v0.2.2 标签，也不将新二进制混入原标签附件。本轮仅推送源码和 GitHub 标签；安装包附件与商店更新未发布。

## 症状与只读证据

用户反馈 Linux 鼠标控制 Mac 顺滑，但 Mac 触控板控制 Linux 明显卡顿，且后者此前曾经顺滑。

- 最近的对应会话使用局域网直连，Mac 位置中转计数为 0；不能简单归因为自动模式走了中转。
- Mac 发送排队通常小于 1 ms；接收侧提交排队出现约 200–360 ms 的长尾。该统计包含接收路由／屏障等待和原生提交，不等同于显示延迟。
- 新增的实体键鼠接管监视器只在 Linux 接收角色运行。原实现从 `wl_input_enter()` 同步扫描，并在 GLib 主循环每秒重复扫描 `/dev/input`；扫描中的设备打开、能力查询及关闭均可能阻塞，同一主循环还负责虚拟指针注入。
- 用生产扫描代码做纯能力元数据查询（不运行事件循环，不读取键鼠事件），初次耗时 438.568 ms，后续四次分别 543.875、463.962、415.982、475.892 ms；停止监视时设备关闭耗时 143.985 ms。此接收角色独有的同步阻塞与方向差异、提交长尾相符。

## 修复

- 设备枚举、打开和能力查询移到 GTask 工作线程；FD 关闭／回收也离开图形主线程。
- 主线程只安装已发现设备的非阻塞活动监视，保留实体输入接管及虚拟设备排除规则；不改键鼠位移、DPI／触控板增益、滚动、网络模式或系统权限。
- 线程仅接收不可变路径快照；停止、重启监视后用代次和取消对象检查丢弃旧扫描结果，防止旧回调重新安装监视。
- 每个接收代次最多一项扫描在途，热插拔继续支持；能力就绪状态改为异步通知。

## 无图形桌面的回归

`linux-local-input.c` 编译生产监视器，但将全部输入节点和系统调用替换为私有假设备；不使用真实输入事件、显示器或剪贴板。故意让设备查询耗时数百毫秒、关闭也延迟，检查主循环心跳、过期扫描、快速停止／重启、实体活动回调、热插拔与 FD 平衡。

```sh
cc -std=gnu11 -O2 spec-tests/linux-local-input.c \
  $(pkg-config --cflags --libs gio-2.0 gio-unix-2.0) \
  -o spec-tests/.run-ac/linux-local-input
spec-tests/.run-ac/linux-local-input
```

- 普通回归多次通过，模拟慢设备时主循环心跳最大间隔约 11 ms；这不是桌面显示／输入延迟测量。
- AddressSanitizer／UndefinedBehaviorSanitizer 回归通过（`detect_leaks=0`，不宣称完成通用内存泄漏检测），旧扫描无回调污染，9 个假 FD 全部回收。
- 原生会话门控、Omarchy 整数输入序列化、共享核心 23 项回归通过，Linux 完整构建通过。

## 部署与边界

仅 Linux 客户端以 `0.2.2+receiver-scan.1` 后台构建更新；已确认更新前无活动控制、光标不在边缘，未暂停其他设备、未打开测试窗口、未注入输入或改变前台焦点。配置字节、身份指纹、布局及各独立开关保留。二进制 SHA-256：`58422d15e623c1e0f7e1d9322d89dd70246f95b52558c6ab698bacc814ccb7ee`。

更新后用户手动反馈：“现在丝滑多了”，并授权提交、推送及创建 GitHub v0.2.3 标签。此反馈确认 Mac 触控板 → Omarchy 的主观流畅度明显改善，不扩大为六方向全部键鼠动作、实体接管、热插拔或蓝牙硬件验收。用户未逐项报告连续移动、停手后继续、跨回等分项结果；已有综合 AC 继续保持 draft。
