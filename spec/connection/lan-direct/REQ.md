# 局域网优先的设备接力

## 背景

用户在同一局域网中用 Mac 控制 Linux 时，中枢转发路径出现间歇延迟。用户已同意采用局域网直连优先、常驻中枢控制连接和中转兜底的方案，并要求更新两端客户端及 LPK 后手动验收。

## 需求目标

- 同一账号的新版客户端自动发现并认证局域网对等连接，实时输入优先走直连；连接状态可观察。
- 连接短暂停顿时不会逐条回放过期光标位置，累计移动距离保持正确；点击和拖拽动作与其位置一致。
- 直连不可达或中断时自动中转，恢复后自动回到直连；切换不重复按键或按钮动作。
- 控制端计算光标位置及跨屏归属，中枢持续负责认证、布局、控制会话和兜底转发。
- 管理页面与 Mac、Linux 本地客户端支持自动（局域网优先）、仅蓝牙、仅局域网、仅中转四种模式，并同步账号设置。仅蓝牙不可用时停止控制，不回退网络；仅中转关闭蓝牙服务、连接、局域网 UDP 监听和探测。
- 管理页面提供暂停全部设备接力的总开关，撤销当前授权并关闭直连入口；管理连接保留以便恢复。
- 客户端和管理页面分别显示光标与键盘的逻辑通道状态；诊断日志分别记录实际路径、位置更新节拍和可靠事件确认，不记录输入字符。
- 保留现有触控板滚动、跨屏交接、紧急收回和旧客户端互通。

## 范围

Mac、Linux 客户端的原生加密直连、输入路由、中枢会话与协议、客户端状态显示、构建和安装更新。自动模式探测局域网 IPv4，其他网络继续中转。蓝牙模式使用 Mac 和 Linux/微服宿主机的真实蓝牙适配器，保留同账号双向证书认证与当前控制会话校验；容器通过只传递蓝牙连接描述符的本机桥接访问宿主硬件，桥接不提供命令、文件或输入注入接口，不新增 IP 监听端口。

## 非目标

更改系统网络或无线设置、部署公网穿透服务、更新 Windows 客户端、承诺消除底层无线链路的全部延迟。人工手感验收由用户完成，不将编译或协议测试当作人工验收。
