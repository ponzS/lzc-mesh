# 原生直连协议 v1

## 认证与发现

客户端通过现有账号会话连接中枢，完成[设备持有证明与首次批准](../device-trust/protocol.md)后发送 `direct_hello`。它包含版本号、进程内临时证书及局域网 IPv4 UDP 候选地址。私钥只留在本机内存。中枢仅向同一账号已注册的原生客户端分发 `direct_peers`，不向普通页面分发证书。

QUIC 使用 TLS 1.3 双向证书认证：客户端只信任目标设备经中枢公布的证书，服务端只信任该账号中枢公布的对端证书。连接完成后再次核对证书与设备 ID 的对应关系。端口不提供命令执行、文件读取或通用 RPC，只承载经过白名单校验的输入消息。

只自动拨号到局域网私有 IPv4 候选地址，不进行 UPnP 端口映射或公网穿透。容器内客户端可向另一端的局域网监听地址发起连接，同一 QUIC 连接双向使用。

## 控制会话

`direct_begin` 申请控制权。中枢检查账号、设备、共享状态和屏幕邻接关系，使用操作系统安全随机源生成会话 ID，以 `direct_session` 通知新版客户端。接收端要求输入的会话、来源、目标均与授权一致；连接本身经过认证并不自动获得输入权限。

控制端计算共享光标位置和屏幕归属。交接发送可靠的离开／进入消息并以 `direct_route` 同步中枢。兼容输入格式仍可经中枢计算位置，但客户端同样必须完成设备批准；不为无设备凭证的旧版本绕过身份要求。

控制端每秒续约，中枢向接收端更新授权。管理连接断开立即关闭直连和释放控制；连续 6 秒没有收到有效续约也会停止输入。`direct_stop`、设备离线、布局变更和全局暂停均撤销当前会话。

## 跨屏光标自动居中

账号设置 `auto_center` 默认开启，并随中枢状态同步和持久化；关闭时保留原有共边比例入口。Mac、Windows 本地设置与管理页修改同一个中枢设置，不通过输入链路另行传播配置。旧中枢未提供此字段时，共享核心保留边缘入口，避免本机旧配置覆盖账号选择。

中枢负责兼容转发的累计坐标和首次原生授权坐标，共享核心负责原生会话后续跨屏的累计坐标。开启时，进入目标、经过第三台设备以及跨回控制端的落点为目标屏幕中央；关闭时按原共边比例落点。输入接收端应用发送端或中枢提供的坐标，不再独立居中，否则下一条绝对移动或点击会跳回旧坐标。主动收回／急停沿用既有释放和恢复规则，不改变授权、位移增益或滚动算法。Omarchy 使用共享核心生效，本轮未增加 Linux 本地设置开关。

## 本机实体输入接管

状态中的 `active.control_id` 唯一标识当前控制会话；原生直连会话复用其安全随机会话 ID，兼容中转会话也生成独立 ID。原生接收端检测到真实本机活动后，先在本机拒绝旧会话注入、释放远程按键／按钮，再通过管理连接发送 `takeover {control_id}`。中枢只接受同账号已批准、启用且正在接收该会话的设备请求，撤销旧授权并恢复控制端；来源设备、第三台设备、跨账号及过期 ID 不能冒充接收端。接管不会自行把键盘转发到其他设备，仍需从布局共边发起新会话。

Windows 使用低级输入事件的注入标记区分本机输入，并用接收代次约束跨线程通知；接管期间先安全清除远程状态，再交付本机触发输入。Mac 排除本应用注入事件与其他进程合成事件，角色切换解除捕获并恢复本应用隐藏的光标；接收入口只做一次位置恢复，保持后续位移与滚动算法。Omarchy 仅在受控期间读取已有权限的物理 evdev 节点，按键值不记录、不落盘，不抢占设备、不修改权限；Wayland 虚拟输入不经过这些物理节点，避免注入回流触发接管。缺少读取权限时明确告警，不声称自动接管可用。

共享核心拒绝已结束会话重新激活。原生回调携带 `_control_session`，本机接管立即封锁已排队的旧会话回调；控制端、接收端角色互斥。锁屏、安全桌面及操作系统权限限制仍然生效，不提供自动解锁或权限绕过。

键码和按钮编号必须发送 JSON 整数。核心兼容历史原生适配层的整值浮点数，但拒绝小数、负数、零和越界编号，不能将无效右键等编号默认为左键。

## 输入顺序与路径切换

- 所有位置为控制端累计计算的绝对共享坐标，附带单调位置序号；移动更新可以合并和丢弃，后续位置不会丢失累计位移。
- 每个目标设备有独立的可靠动作序号。移动携带动作屏障，接收端在对应按键／按钮动作之前不会应用后续移动。
- 点击、按键和滚动消息走可靠流，并携带对应位置；动作执行前先定位，重复消息只确认、不重复注入。
- 直连不健康时，新移动自动通过 `direct_relay` 转发。未确认动作在短暂超时后通过中转补发，序号保证去重。仅直连模式禁止此兜底。
- 中转路径也验证当前来源和会话，并保留相同的消息和确认格式；旧会话不能借路径切换重新生效。
- 光标移动在有输入时立即发送；仅合并已经排队的更新，不等待周期性发送节拍。维护定时器只负责心跳、续约和重试。
- Linux 虚拟指针使用每像素 4096 个坐标单位并正确舍入，避免归一化还原后提前截成整像素。
- 原生 UI 交接队列只替换相邻移动消息，不跨越点击、按键、滚动或跨屏动作进行合并。

## Windows 管理发送隔离

Windows 的中枢发送进入当前连接专属的有界 FIFO，由独立写线程调用网络 API；输入注入线程不等待网络写入。关闭连接清空未发送队列，重连建立新队列与句柄，旧回调按连接代次丢弃。队列超限时安全断开并释放输入，不静默丢失可靠控制消息。此隔离不取消管理授权租约，也不承诺消除无线链路抖动。

## Windows 接收输入与窗口隔离

Windows 的原生回调和兼容中枢输入直接进入独立、有界、串行的接收执行队列，输入注入、远程按键重复定时器和本机接管释放不经过主窗口消息派发。主窗口只接收经过代次校验的角色与状态通知。否则，远控点击客户端自身标题栏时，系统按钮跟踪循环可能等待鼠标松开，而松开又等待同一 UI 线程处理自定义消息。

原生会话门控由接收执行线程唯一维护；只合并相邻、同会话的绝对移动，不跨越按钮、按键、滚动或交接。中枢断线、设备停用、撤销、暂停及队列超限使旧队列失效并释放按键、按钮与重复状态。超限在本次管理连接内保持停用，不由普通界面刷新重新开启。中转输入、原生授权续约、可靠确认与蓝牙字节处理同样不能依赖主窗口继续派发。发送回调绑定管理连接代次，不能写入重连后的新连接。

控制端捕获和窗口覆盖层仍由 UI 管理；接收端开始工作或控制结束时先原子取消源端捕获，迟到的 UI 角色通知不能重新捕获。操作系统权限及安全桌面限制不变。最小化时跳过无效尺寸布局，恢复窗口时按最新状态重新布局；点关闭仍只隐藏到托盘，不退出或停用共享。

## 页面设置与关闭入口

账号级设置 `transport_mode` 为 `auto`、`bluetooth`、`direct` 或 `relay`。自动模式优先可用直连；仅直连不可达时停止控制；仅中转关闭现有蓝牙与 QUIC 连接、移除蓝牙服务、停止拨号并释放 UDP socket，仅保留中枢管理连接。设置持久化并在上线后先接收设置再建立监听。

`input_enabled=false` 是账号级急停：中枢撤销会话、禁止新控制，客户端释放按键／按钮并关闭直连入口。恢复后需要重新跨屏。急停不能撤销已经执行的桌面动作，也不声称能够约束已被攻陷而不再运行正常代码的系统。


## 指针诊断

原生采集回调通过共享进程内单调时钟标记移动，最多每 125 ms 采样一次。来源端记录捕获回调到发送队列的等待；接收端记录数据进入传输工作线程到原生坐标提交的等待，并回送低频采样回执。所有间隔均在同一进程内计算，回执往返也只使用来源端时钟，不依赖两台电脑时钟同步。

`pointer_metrics` 日志输出源端排队、接收端提交排队、提交后回执往返的中位数和 p95。这里的提交表示坐标已交给操作系统，不代表屏幕已经显示；回执往返不能当作鼠标单程延迟或触控板体感。统计不记录按键内容或屏幕画面。


光标和键盘是同一 QUIC 连接上的独立逻辑传输机制；两者共享底层网络和拥塞控制。客户端及页面以 `pointer` / `keyboard` 分别展示状态，来源是最近实际发送／接收的路径，没有流量时显示就绪。中转模式下两类消息仍共享管理 WebSocket。

`pointer_metrics` 另记录捕获回调的事件间隔、位置实际直发／中转／未发送计数；`pointer_rx_metrics` 记录收到位置包的间隔。间隔包含用户停止移动的时间，不能直接将间隔较长或位置序号跳跃解释为丢包。`keyboard_metrics` 记录可靠按键事件的直发／中转数量及传输确认往返；该确认不等同于字符已经显示。已去除原生接收端按键编码的逐条日志。


Mac 控制端以相对位移采集，捕获开始及持续控制期间不再将本地光标回正。绝对位置用于边缘检测和结束控制后恢复，不用于累计远端移动，以避免周期性光标回正引起硬件输入抑制。原有跟踪增益保持不变。


为避免用户停手时最后一个不可靠位置包丢失后停在旧位置，来源端在没有后续输入时，最多在 20/60/120 ms 对最新绝对位置做有界重复。重复使用同一会话和位置序号，接收端去重，不回放历史轨迹；新移动立即替换缓存，点击等可靠动作和会话结束清除缓存。这不增加新移动的发送等待。

## 蓝牙通路（0.2.0）

`transport_mode=bluetooth` 是严格蓝牙模式。`direct_hello` / `direct_peers` 可携带 `bluetooth` 对象：Mac 为 `role=listener`，提供经典蓝牙地址与 RFCOMM channel（1..30）；Linux 为 `role=connector`。中枢对长度、角色及地址格式进行限制。蓝牙模式的候选 UDP 地址为空，不创建 QUIC 监听；非蓝牙模式移除蓝牙服务和连接。中枢同时禁止蓝牙模式的旧输入中转和 `direct_relay`。

RFCOMM 服务 UUID 为 `F4174C12-5A3B-4429-B265-06EEDCEFE21A`，服务临时发布，不设置持久自启。RFCOMM 字节流上使用 Rustls 双向 TLS，ALPN `lzc-mesh/bt/1`。客户端只信任指定目标证书，服务端只信任同账号已发现设备；握手后再次匹配证书与设备 ID。更换/撤销证书会关闭旧连接，未完成握手的连接最多等待 8 秒，未收到有效协议数据的已认证连接最多保留 4 秒。

加密前维护有界动作队列，最多 128 条，只有相邻且会话、目标、动作屏障一致的无动作位置可被更新位置替换。每次原生层完成一个加密块的发送后才继续出队。TLS 记录不可丢弃；超限和认证失败关闭连接。所有输入继续使用当前控制会话与序号校验。物理链路可靠有序，光标与键盘没有独立物理通道，不声称其消除了蓝牙底层重传的等待。

Linux 宿主描述符桥接只接受指定 Unix peer UID，支持能力查询、连接到合法蓝牙地址及 RFCOMM channel。Linux 取消或切换模式会关闭尚未完成的桥接请求，宿主取消连接并释放描述符。桥接启动后降权至普通 UID；没有 IP 监听、输入注入、文件访问或命令接口。部署与路径映射见客户端 `BLUETOOTH.md`。
