# 设备身份协议 v1

## 身份与信任

每台客户端生成并持久保存 Ed25519 设备密钥。macOS 使用不参与同步的 Keychain 项，Windows 使用当前用户 DPAPI 保护，Omarchy 使用拒绝符号链接的当前用户专属 0600 文件。已有凭证读取失败时停止共享，不自动生成替代身份。设备 ID、布局偏好与私钥分别管理。

客户端以 `device_hello` 提交原设备 ID、公开元数据及标准 Base64 编码的 32 字节公钥。中枢回复 `device_challenge`：账号与 32 字节随机 nonce。客户端签名以下 UTF-8 JSON 数组的紧凑编码，并以 `device_proof.signature` 返回 Base64 签名：

```text
["lzc-mesh/device-proof/v1", account, device_id, public_key_base64, nonce_base64]
```

挑战绑定当前管理连接，30 秒有效且只消费一次。错误、过期、重放或与已绑定公钥不匹配的请求不能改变原设备、布局或控制会话。公钥指纹为公钥原始字节的 SHA-256 小写十六进制，完整 64 字符。

持有证明通过后，新设备登记为待批准。管理页发送 `device_trust`，携带设备 ID、所核对的完整指纹和 `approved`。中枢按当前账号匹配已证明公钥；旧指纹不能批准新的绑定。批准状态独立于持久化的 `enabled` 休眠开关。无凭证的旧版客户端必须升级，不因同账号或旧设备 ID 自动获信任。

`state.devices` 另含 `trusted`、`fingerprint` 和 `approval_status`。待批准设备只看到自己的状态，不收到其他设备拓扑、证书或自动剪贴板/文件数据。`device_auth` 通知本机已批准、待批准、已撤销或凭证不匹配。已批准身份重连无需再次批准；同一身份的新连接使原连接和原文件凭证失效。

## 直连及权限撤销

只有已批准的连接能够公布临时 QUIC/TLS 证书。证书经账号内已证明的连接分发，继续沿用双向 TLS、当前输入授权、序号及屏障校验。设备级签名只用于注册，不用于每次键鼠事件；不增加逐输入的中枢鉴权往返。QUIC 握手并发有界，但不声称可以抵御底层网络拒绝服务。

撤销或休眠中止对应控制、撤销证书公布并取消原生文件流；重新批准不重放旧输入或恢复旧任务。管理连接仍可观察待批准状态，客户端启停不能代替批准。授权租约和管理断线安全释放规则保留。

## 原生文件请求

批准连接收到独立的随机文件凭证 `device_auth.token`，仅存活于当前已批准连接。原生 HTTP 请求同时携带 `X-Lzc-Mesh-Device-Id` 与 `X-Lzc-Mesh-Device-Token`；设备显示名称不能作为身份凭证。中枢按账号、批准状态、运行状态和活跃连接校验；撤销、重连与休眠会取消原传输，即使随后快速恢复也不恢复旧请求。

浏览器文件管理使用账号管理权限，不属于某台原生设备。管理网页登录会话本身具有批准设备和管理文件的权限，设备绑定不能防止管理会话被盗；HTTP/WebSocket 拒绝显式跨来源的浏览器请求。不把可伪造的 Origin、User-Agent 或设备名称作为密码学凭证。

## 账号存储隔离

账号目录使用无歧义、长度有界的映射。仅由字母、数字和连字符组成的账号保留原位置；含下划线或其他字符的账号使用带保留前缀的 SHA-256 命名空间。历史替换字符形成的目录可能归属不明，因此不自动认领或迁移，也不删除；如需恢复旧数据必须由管理员确认归属后迁移。

## 权限边界

客户端默认普通用户运行，不增加命令执行或提权接口，不绕过系统安全桌面。合法键鼠控制仍具有当前桌面用户的实际操作能力，不能保证其无法操作已提权终端。私钥、文件凭证、签名应答和剪贴板正文不进入诊断日志。
