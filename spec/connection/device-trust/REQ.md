# 设备凭证与首次批准

## 背景

局域网输入服务不能以 IP、设备名称或可复制的设备 ID 作为身份凭证。同账号发现仍需区分已批准设备与待批准设备，并在撤销后阻止原凭证继续控制或共享。

## 需求目标

- 每台客户端安全保存持久设备私钥，通过持有证明完成注册；中枢按账号保存公钥与批准状态。
- 新设备与升级前未绑定凭证的设备首次接入均需在管理页核对指纹并批准，之前不获得输入会话、对端证书或自动共享数据。
- 已批准设备重连和重启后保持信任、设备 ID、布局、休眠选择与系统输入权限；凭证损坏时明确停止，不静默更换身份。
- 批准、撤销信任与客户端休眠相互独立。撤销结束控制、释放输入、取消原生文件任务并撤销直连凭证；重新批准后只恢复新操作。
- 输入使用已有双向认证 QUIC/TLS，本地检查当前会话及防重放，不为每次键鼠事件请求中枢鉴权或增加设备级数字签名。
- 客户端默认普通用户运行，不自动提权，不新增远程命令或提权服务。

## 范围

macOS、Windows、Omarchy 客户端的身份存储、注册与状态显示，共享传输凭证验证，中枢、管理页及原生文件授权。Linux 客户端仅支持 Omarchy。现有三端升级后也需首次确认一次。

## 非目标

防止已被攻陷的操作系统或被盗账号管理凭证执行其已有权限；管理网页登录会话拥有批准设备与管理文件的账号权限。设备认证不能保证合法远控无法操作已提权终端。浏览器文件管理不作为某台原生设备。不会削弱加密、绕过安全桌面、改变 Mac/Linux 的位移及滚动算法，或自动修改系统配对、路由和防火墙。
